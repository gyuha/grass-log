# 하루의 경계를 GitHub 프로필 타임존에 위임한다

일일 로그의 "하루"를 코드에 박은 `Asia/Seoul`이 아니라 GitHub이 정하는 하루로 정의한다. `contributionsCollection`의 `from`/`to`가 시각 성분을 무시하고 계정 프로필 타임존 기준의 하루 단위로 버킷팅하기 때문에, 명시적 KST 경계는 애초에 이 API로 표현할 수 없다. 위임을 택하면 로그의 날짜와 잔디 그래프의 날짜가 정의상 일치한다 — 이 프로젝트의 목적이 정확히 그것이다.

## Considered Options

- **UTC 하루** — 기여 그래프와 최대 9시간 어긋난다. KST 오전 0~9시 활동이 전날 로그로 밀리고, KST 22:00 실행 시점에 당일 UTC 하루가 아직 11시간 남아 로그가 미완성으로 커밋된다. 기각.
- **명시적 `Asia/Seoul` 경계** — `contributionsCollection`이 오프셋을 무시하므로 구현 불가. 리포 목록을 다른 API로 얻어 우회할 수 있으나, 그러면 집계가 그래프와 어긋날 수 있고 "왜 그래프와 숫자가 다른가"라는 항구적 혼란을 만든다. 기각.
- **GitHub 위임** — 채택.

## Consequences

경계 규칙이 GitHub의 미문서화 동작에 의존한다. 근거는 관측이다: `from: 2026-08-19T00:00:00Z, to: 2026-08-19T23:59:59Z` 조회에서 이슈 #13(11:12Z)·#12(11:07Z)는 잡히고 #14(22:40Z)는 빠졌으며, #14는 8/20 조회에 나타났다. 22:40Z가 8/20에 귀속된다는 것은 UTC가 아닌 양수 오프셋 타임존 버킷팅을 의미한다(+1:20 ~ +12:48 구간이면 모두 설명 가능하므로 KST 확정은 추론이다).

이 추론이 틀렸거나 GitHub이 동작을 바꾸면 로그 날짜가 조용히 밀린다. 그래서 로그마다 그래프 카운트 기준 커밋 수와 히스토리 목록화 커밋 수를 함께 적고 **불일치를 명시 기록**한다 — 경계 가정이 깨지는 순간 로그 자체에 드러나게 하는 자기진단 장치다.

되돌리는 비용: 경계를 바꾸면 그 이전에 쌓인 모든 로그 파일의 날짜 귀속이 달라져 아카이브가 불일치해진다.
